> 작성일: 2026-11-20 · 상태: **초안 (결정 대기 항목 있음 → §10)**
> 작업 이름: **ListenUp** (가칭)

## 1. 목표와 문제 정의

### 1.1 해결하려는 문제
한국인 학습자가 영어 듣기에서 겪는 핵심 장애는 대체로 세 가지다.

| 장애 | 증상 | 원인 |
|---|---|---|
| **소리 인식** | "아는 단어인데 안 들린다" | 연음·축약·약화(connected speech), 한국어에 없는 음소 구분(r/l, f/p, b/v, θ/s) |
| **처리 속도** | "천천히 하면 아는데 원어민 속도면 놓친다" | 자동화 부족, 단기기억 과부하 |
| **어휘·배경지식** | "들리긴 하는데 무슨 뜻인지 모른다" | 어휘량, 표현·맥락 지식 부족 |

대부분의 앱은 "많이 들려주기"(extensive listening)에 치우쳐 있고, **"왜 못 들었는지"를 진단하고 그 지점을 반복 훈련시키는 기능**이 약하다. 이 앱의 차별점은 여기에 둔다.

### 1.2 제품 목표
1. **놓친 소리를 정확히 찾아낸다** — 받아쓰기 결과를 단어 단위로 비교해 오류 유형(연음/음소/어휘)을 분류.
2. **놓친 지점만 집중 반복한다** — 문장 단위 루프, 속도 조절, 간격 반복(SRS)으로 재출제.
3. **모바일·데스크톱 어디서든 이어서 한다** — 출퇴근은 모바일(듣기·쉐도잉), 집중 학습은 데스크톱(받아쓰기 타이핑).

### 1.3 성공 지표 (개인용 기준)
- 받아쓰기 단어 정확도(1 − WER)가 같은 난이도 콘텐츠에서 8주 후 +15%p 이상
- 주 4일 이상, 하루 15분 이상 학습 유지
- 1.0x 속도에서 "첫 청취 이해도" 자기평가 상승

## 3. 하위 문제별 해결안 (SOLVE + 신뢰도)

### P1. 학습 방법론 — 신뢰도 0.85
연구·현장에서 효과가 비교적 잘 확인된 방법들을 조합한다.

| 훈련 모드 | 방법 | 겨냥하는 장애 |
|---|---|---|
| **① 블라인드 청취 → 스크립트 확인** | 자막 없이 1~2회 → 이해도 자기평가 → 스크립트 공개 | 처리 속도, 이해 |
| **② 받아쓰기 (Dictation)** | 문장 단위로 듣고 타이핑, 단어별 정오 표시 | 소리 인식 (가장 진단력이 높음) |
| **③ 집중 반복 (Intensive loop)** | 문장 A-B 반복, 0.5x~1.5x 속도, 단어 탭 시 해당 구간 재생 | 소리 인식 |
| **④ 쉐도잉 (Shadowing)** | 0.3초 지연으로 따라 말하기, 녹음 후 원음과 비교 | 처리 속도, 연음 체화 |
| **⑤ 연음·음소 드릴** | 최소대립쌍(light/right), 축약(wanna, gonna, didja) 판별 퀴즈 | 소리 인식 |
| **⑥ 복습 (SRS)** | 놓친 문장·표현을 FSRS 알고리즘으로 재출제 | 장기 정착 |

**학습 흐름 (1 세션 ≈ 15분)**
```
레벨 맞춤 콘텐츠 선택 → ① 블라인드 청취 → ② 받아쓰기
  → 오류 분석 → ③ 틀린 문장 집중 반복 → ④ 쉐도잉(선택)
  → 틀린 문장/표현 SRS 카드로 자동 저장 → 다음 날 ⑥ 복습
```

**오류 자동 분류 (차별화 핵심)**
- 받아쓰기 입력과 정답을 정규화(대소문자·구두점·축약형·숫자 표기) 후 단어 정렬(diff)
- 틀린 단어를 규칙 기반으로 분류:
  - *연음/약화*: 기능어(a, the, to, of, and, have…)·축약 위치에서의 누락
  - *음소 혼동*: 철자상 최소대립쌍에 해당하는 치환 (ex. `light`↔`right`)
  - *어휘*: 사용자가 해당 단어 뜻을 모른다고 표시했거나 저빈도 단어
- 누적 통계 → "당신은 `to`/`the` 약화 구간을 자주 놓칩니다" 같은 진단 리포트

### P2. 콘텐츠 확보 — 신뢰도 0.70 (가장 불확실 → §5 REFLECT)
| 소스 | 장점 | 단점/리스크 | 채택 |
|---|---|---|---|
| **AI 생성 스크립트 + 신경망 TTS** | 레벨·주제·억양(미/영/호) 자유, 저작권 깔끔, 단어 타임스탬프 확보 쉬움 | 자연스러운 망설임·겹침 부족, TTS 비용 | **MVP 주력** |
| **퍼블릭 도메인** (VOA Learning English 등 미국 정부 저작물, LibriVox) | 실제 사람 음성, 무료 | 주제·레벨 제한, 출처별 라이선스 개별 확인 필요 | 보조 |
| **사용자 가져오기** (내 오디오 + 자막 파일) | 원하는 콘텐츠로 학습 | 개인 사용에 한정, 앱에서 배포 불가 | v2 |
| YouTube 오디오 추출 | 콘텐츠 풍부 | **이용약관 위반** | ❌ 제외 |

**콘텐츠 파이프라인 (오프라인 배치 처리)**
```
LLM으로 레벨별 대화/독백 스크립트 생성 (CEFR A2~C1)
  → TTS로 음성 합성 (화자 2명, 억양 다양화)
  → 문장 분할 + 단어 타임스탬프 (TTS 제공값 또는 Whisper 강제 정렬)
  → 어휘·연음 포인트 메타데이터 태깅
  → 콘텐츠 번들(JSON + 오디오) 생성 → 앱에 배포
```

### P3. 플랫폼/기술 스택 — 신뢰도 0.75
요구사항: iOS·Android·Windows·macOS 단일 코드베이스, 정밀한 오디오 제어(구간 반복·속도 변경 시 피치 유지), 오프라인, 녹음.

| 후보 | 장점 | 단점 |
|---|---|---|
| **Flutter** (권장) | 모바일+데스크톱+웹 1개 코드, `just_audio`(구간·속도·피치 보정), 녹음 패키지 성숙, UI 일관성 | Dart 학습 필요 |
| React Native + Electron | JS 생태계 | 코드베이스 2개, 데스크톱 오디오 처리 별도 |
| PWA (웹앱) | 가장 빠른 시작, 설치 불필요 | iOS 백그라운드 재생·오프라인 제약 |
| Tauri 2 + React | 가벼운 데스크톱, 모바일 지원 | 모바일 지원이 상대적으로 덜 성숙 |

**결정(잠정): Flutter**
- 로컬 DB: SQLite (`drift`)
- 오디오: `just_audio` + `audio_service`(백그라운드 재생/잠금화면 제어)
- 녹음: `record`
- 상태관리: Riverpod
- 개발 환경 참고: 클라우드 컨테이너에서는 **Flutter Web/Linux 빌드로 로직·UI 검증**, iOS/Android 실기기 테스트는 로컬 PC에서 진행

### P4. 핵심 엔진 — 신뢰도 0.85
| 모듈 | 구현 방식 |
|---|---|
| 문장 플레이어 | 문장별 `[start, end]` 타임스탬프로 클리핑 재생, A-B 루프, 0.5~1.5x |
| 받아쓰기 채점 | 정규화 → 단어 단위 Levenshtein 정렬 → 정오/누락/추가 표시, 철자 오류는 편집거리 1~2면 "부분 정답" |
| 오류 분류기 | 규칙 기반(기능어 목록, 최소대립쌍 사전, 축약형 사전) — v1은 LLM 없이 로컬 처리 |
| SRS | FSRS 알고리즘(오픈 소스, Anki 채택) — 카드 = 문장 오디오 + 정답 + 내가 틀린 부분 |
| 쉐도잉 비교 | v1: 녹음 + 원음 번갈아 듣기 / v2: 음성인식(Whisper)으로 일치율, 발음 평가 API 검토 |
| 레벨 측정 | 초기 10문항 받아쓰기 테스트로 CEFR 대략 추정 → 이후 정확도로 자동 조정 (목표 정확도 70~85% 구간 유지) |

### P5. 데이터·동기화 — 신뢰도 0.80
- **로컬 우선(local-first)**: 모든 학습 기록은 기기 SQLite에 저장 → 오프라인 완전 동작
- **동기화(v1.5)**: Supabase(Postgres + Auth) 또는 단순 백엔드로 학습 기록·SRS 상태 동기화, 충돌은 "최근 수정 우선 + 리뷰 로그는 합집합"
- 콘텐츠 번들은 정적 파일(CDN/Object Storage)로 배포, 기기에 캐시

## 4. 검증 (VERIFY)

| 점검 항목 | 결과 |
|---|---|
| **논리** | 핵심 가설 "진단(받아쓰기) → 집중 반복 → SRS"는 듣기 장애 세 유형과 1:1 대응됨. 어휘 장애는 단어 탭 → 뜻 보기 + 단어 카드로 보완 ✅ |

## 5. 약점 보완 (REFLECT — 신뢰도 0.8 미만 항목)

### P2 콘텐츠 (0.70 → 목표 0.80)
- **약점**: TTS 음성의 부자연스러움, 실제 음성 소스의 라이선스 불확실성
- **보완**:
  1. TTS 스크립트에 구어체 요소(filler: "you know", "I mean", 자기수정)를 의도적으로 포함하도록 생성 프롬프트 설계
  2. 퍼블릭 도메인 소스는 **화이트리스트 방식**으로 출처별 라이선스를 문서화한 것만 사용
  3. v2에서 "내 파일 가져오기"로 사용자 개인 콘텐츠 학습 지원 (배포 없음 → 저작권 리스크 사용자 개인 범위)
  4. MVP 전에 TTS 2~3종 샘플을 만들어 직접 들어보고 선택 (§7 Spike)
- **보완 후 신뢰도: 0.80**

### P3 기술 스택 (0.75 → 목표 0.80)
- **약점**: 플랫폼별 오디오 동작 차이(특히 데스크톱의 구간 반복 정밀도, 속도 변경 시 피치 유지)
- **보완**: 본 개발 전 1~2일 기술 검증(Spike) — Windows/macOS/Android/iOS에서 50ms 이내 구간 반복 정밀도, 0.75x 피치 유지를 확인. 실패 시 대안: 데스크톱만 미디어킷 플러그인 교체
- **보완 후 신뢰도: 0.80**

### P6 일정 (0.70)
- **약점**: 개발 투입 시간(주당 시간)·출시 여부가 미정이라 일정 추정 불확실
- **보완**: 기간 대신 **마일스톤 + 완료 기준**으로 관리. §10 답변 후 일정 재추정
- **보완 후 신뢰도: 0.75** (사용자 결정 전까지 상한)

## 7. 화면 구성 (초안)

```
[홈]        오늘의 학습(복습 N개 + 새 콘텐츠) · 연속 학습일 · 주간 정확도 그래프
[라이브러리]  레벨/주제/억양/길이 필터 · 진행률
[학습]      ① 블라인드 청취 → ② 받아쓰기 → ③ 집중 반복 → ④ 쉐도잉 (단계 탭)
[복습]      SRS 카드: 오디오 재생 → 받아쓰기 → 정답 비교 → 난이도 평가
[리포트]    오류 유형 분포 · 자주 놓치는 단어/패턴 TOP 10 · 레벨 추이
[설정]      기본 속도, 억양 선호, 알림, 데이터 내보내기
```
- **모바일**: 한 손 조작 — 하단 큰 재생/반복/느리게 버튼, 이어폰 버튼으로 문장 반복
