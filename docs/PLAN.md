## 변경 이력
- **v0.3**: 예산 = 무료 TTS(Kokoro), 하루 학습 1시간, 주당 테스트 1시간, 기기 = Android 폰 + Windows PC로 확정. 학습 시간 1시간에 맞춰 콘텐츠 공급량 상향. 빌드는 GitHub Actions에서 APK와 Windows 실행 파일로 생성. 오디오 패키지를 `audioplayers`로 변경(M0 검증 결과).
- **v0.2**: 개인용으로 확정. 시작 수준은 "거의 안 들림". **20단계 커리큘럼**(미국 유치원 → 대학, 일상 대화 + 뉴스) 추가. 콘텐츠를 계속 확보하는 체계 추가. Flutter 확정. **클래식 뮤직플레이어 감성의 휠 UI** 추가.
- v0.1: 초안

## 1. 목표

### 1.1 해결하려는 문제
| 장애 | 증상 | 원인 |
|---|---|---|
| 소리 인식 | "아는 단어인데 안 들린다" | 연음·축약·약화, 한국어에 없는 음소 구분 |
| 처리 속도 | "느리면 아는데 원어민 속도면 놓친다" | 듣기 처리가 아직 자동화되지 않음 |
| 어휘·배경지식 | "들리는데 뜻을 모른다" | 어휘, 맥락 부족 |

### 1.2 제품 목표 (개인용)
1. **20단계로 차근차근**: 거의 안 들리는 수준(L1: 75wpm, 2~4단어 문장)에서 시작해 실제 방송 속도(L20)까지 올라간다.
2. **놓친 소리를 진단하고 그 지점만 반복**: 받아쓰기 → 오류 유형 분류 → 집중 반복 → 간격 반복(SRS).
3. **콘텐츠가 끊기지 않게**: 성장 시리즈와 뉴스를 단계별로 계속 자동 생성해서 공급한다.
4. **심플하고 손맛 있는 UI**: 원형 휠 하나로 조작한다.

### 1.3 성공 지표
- 8주 안에 **4단계 이상 진급** (진급 기준: 1.0x 받아쓰기 정확도 85% 이상, 연속 3개)
- 주 5일 이상, 하루 1시간 학습
- 현재 단계에서 미학습 콘텐츠가 바닥나는 일이 0회

## 3. 해결안 (SOLVE + 신뢰도)

### P1. 학습 방법론 — 0.85
| 모드 | 방법 |
|---|---|
| ① 블라인드 청취 | 자막 없이 듣기 → 이해도 자기평가 → 스크립트 공개 |
| ② 받아쓰기 | 문장 단위로 입력, 단어마다 정답·틀림·누락 표시 (진단의 핵심) |
| ③ 집중 반복 | 문장 반복, 0.5~1.5x 속도 |
| ④ 쉐도잉 | 따라 말하고 녹음 → 원음과 번갈아 듣기 |
| ⑤ 소리 드릴 | 단계별로 새로 나오는 연음 특성을 퀴즈로 연습 (예: L8 flap T, L9 gonna/wanna) |
| ⑥ 복습 | 틀린 문장을 FSRS 알고리즘으로 재출제 |

**하루 학습(1시간) 구성안**
| 시간 | 내용 |
|---|---|
| 10분 | SRS 복습 (어제까지 틀린 문장) |
| 35분 | 새 콘텐츠 3~4개: ① 블라인드 → ② 받아쓰기 → ③ 집중 반복 |
| 10분 | ④ 쉐도잉 (오늘 틀린 문장 위주) |
| 5분 | ⑤ 소리 드릴 |

1시간이 부담되는 날은 15분 단위로 끊어도 이어서 할 수 있게 한다(진행 위치 자동 저장).
**오류 자동 분류**: 연음·약화 / 음소 혼동 / 어휘 / 철자. 규칙 기반이고 기기 안에서 처리한다.

### P2. 20단계 커리큘럼 — 0.80
6개 구간 × 20단계: 유치원(L1–3) → 초등 저학년(L4–7) → 초등 고학년(L8–11) → 중학교(L12–14) → 고등학교(L15–17) → 대학(L18–20).
단계마다 **속도, 어휘량, 문장 길이, 클립 길이, 화자 수, 허용하는 연음 특성, 주제**를 정의한다. 연음은 단계마다 하나씩 새로 도입한다.
→ 상세: [CURRICULUM.md §2](./CURRICULUM.md#2-20단계-정의)

**성인 학습자 고려**: 사용자는 읽기 어휘가 이미 높을 수 있으므로, 진급은 *소리 인식 정확도*만으로 판단하고 95% 이상이면 건너뛸 수 있게 한다. 유치원 콘텐츠가 지루하게 느껴질 수 있다는 점은 성장 시리즈의 줄거리로 보완한다.

### P3. 콘텐츠 지속 확보 — 0.80
- 소스 3종: **① 오리지널 성장 시리즈**(가상 인물이 L1→L20 함께 성장) · **② 상시 뉴스**(동물·과학·역사 등 낡지 않는 주제) · **③ 시사 뉴스 재작성**(퍼블릭 도메인 1차 자료의 사실만 가져와 단계에 맞게 새로 씀)
- **주제 매트릭스**(단계 × 주제 × 형식)의 빈 칸부터 우선 생성해서 다양성을 보장한다.
- **자동 품질 검사**: 어휘 범위, 문장 길이, 중복, 실측 wpm 확인
- **공급 규칙**: 하루 1시간이면 새 콘텐츠를 하루 3~4개, **주당 약 25개** 소비한다. 그래서 M1에서 L1~L5에 단계당 30개(150개)를 만들고, 이후 현재 단계 ±1에 주당 25~30개를 보충한다. 같은 원고를 다른 목소리로 다시 합성해 노출을 늘린다.
- YouTube 오디오 추출은 이용약관 위반이라 제외한다.
→ 상세: [CURRICULUM.md §3](./CURRICULUM.md#3-콘텐츠-확보-체계-계속-확보를-위한-구조)

### P4. 기술 스택·핵심 엔진 — 0.80 (Flutter 확정)
| 영역 | 선택 |
|---|---|
| 앱 | Flutter (iOS·Android·Windows·macOS, 검증용 Web) |
| 오디오 | `audioplayers` (Android·Windows·Web 지원, 피치를 유지한 속도 변경) — 백그라운드 재생은 M4에서 `audio_service` 추가 |
| 녹음 | `record` |
| 로컬 DB | SQLite (`drift`) |
| 상태 관리 | Riverpod |
| 받아쓰기 채점 | 정규화 → 단어 단위 편집거리 정렬 |
| 복습 | FSRS |
| 콘텐츠 도구 | `tools/contentgen` (Python CLI): 대본 YAML → TTS(Kokoro, 무료) → 목표 wpm 자동 맞춤 → 번들. 문장 단위로 합성해 문장 타임스탬프가 정확하므로 문장 수준에서는 강제 정렬이 필요 없음 |
| 빌드·배포 | GitHub Actions: push하면 **Android APK**와 **Windows 실행 파일(zip)**이 자동 생성됨 → 사용자가 내려받아 설치 |

### P5. UI — 0.80
클래식 휴대용 뮤직플레이어에서 영감을 받은 **목록 메뉴 + 원형 휠** 구조다. 흑백에 강조색 하나, 햅틱과 클릭음을 쓴다.
- 휠 회전 = 문장 이동 / 길게 누르면 속도 조절 모드, 아래 버튼 = 이 문장 다시 듣기
- 모바일은 위 화면 + 아래 휠, 데스크톱은 마우스 스크롤·키보드를 휠 동작에 대응
- 특정 회사의 로고나 제품 외형은 복제하지 않고, 영감만 받은 오리지널 디자인으로 만든다.
→ 상세: [DESIGN.md](./DESIGN.md)

### P6. 데이터·동기화 — 0.80
기록은 기기에 우선 저장해서 오프라인에서도 완전히 동작한다. 모바일↔데스크톱 이어하기는 M4에서 붙이며, Supabase 무료 범위면 개인용으로 충분할 것으로 예상한다.

### P7. 범위·일정 — 0.80
- **테스트 주기**: 주 1회 1시간. 매주 빌드 1개와 "이번 주 확인할 것" 체크리스트(5~10개)를 받아서 Android와 Windows에서 써보고 피드백한다.
- **기기**: Android는 APK 직접 설치(무료). Windows는 zip을 풀고 실행. 둘 다 스토어나 유료 계정이 필요 없다.
- 개발과 콘텐츠 생성은 Claude 세션에서 하므로 사용자 시간은 테스트·피드백에만 쓴다.

## 5. 약점 보완 (REFLECT)
- **P7 일정 (0.70 → 0.80)**: 기기가 Android와 Windows로 정해지면서 iOS·Mac 문제가 사라졌다. 이 환경에서는 Windows 빌드를 직접 할 수 없지만, GitHub Actions의 Windows 빌드 서버로 해결한다.
- **무료 TTS 품질**: L1·L10·L20 샘플로 사용자가 직접 확인한다. 부족하면 유료 TTS로 바꾸는데, 대본과 파이프라인은 그대로 쓰고 합성 단계만 교체하면 된다.
- **단계 수치 보정**: M2부터 실제 정확도 데이터로 각 단계의 wpm과 어휘 경계를 다시 조정한다.
